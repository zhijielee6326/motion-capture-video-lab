## 案例1：验证型 — 技术栈

### 硬件

| 设备 | 用途 | 备注 |
|------|------|------|
| OptiTrack红外相机阵列 | 动作捕捉空间搭建 | 6-12台覆盖动捕空间 |
| 动捕服+50个反光标记点 | 演员穿戴，骨骼点识别 | 标记点数量最多(50) |
| 图形工作站 | 运行Motive+MotionBuilder+UE | 需要高性能GPU |

### 软件

| 软件 | 版本建议 | 用途 | 许可/获取方式 |
|------|----------|------|---------------|
| **Motive** (OptiTrack) | 2.x+ | 相机标定、标记点识别、骨骼创建、数据流输出 | OptiTrack许可证 |
| **MotionBuilder** | 2023+ | OptiTrack Skeleton插件、角色绑定、实时数据中转 | Autodesk教育许可 |
| **Unreal Engine** | 5.x | 虚拟数字人渲染、LiveLink数据接收 | 免费开源 |
| **LiveLink** (UE插件) | 随UE版本 | MotionBuilder↔UE实时动作数据传输 | UE内置插件 |
| **OptiTrack Skeleton Plugin** | — | MotionBuilder中接收Motive骨骼数据 | OptiTrack提供 |

### 关键技术参数

| 参数 | 合格阈值 | 说明 |
|------|----------|------|
| 残差 (Residual) | ≤1mm | 标定精度指标 |
| Final Rate | 120Hz | 动捕采样帧率 |
| 总延迟 | ≤10ms | 端到端动作延迟 |
| 标记点识别 | 50/50 | 全部标记点成功识别 |

### 数据流架构

```
演员 → [动捕服+50标记点] → Motive(标定+T-Pose+骨骼)
    → UDP → MotionBuilder(OptiTrack Skeleton插件+角色绑定)
    → LiveLink → Unreal Engine(虚拟数字人实时驱动)
    → 远程课堂推流
```

## 案例2：项目/设计型 — 技术栈

### 硬件

| 设备 | 用途 | 备注 |
|------|------|------|
| FZMotion动捕系统 | 动作捕捉核心 | FZMotion为国产光学动捕 |
| Swift30红外相机 | 动捕空间搭建 | FZMotion配套 |
| 动捕服+39点位标记点 | 演员穿戴 | 39个关键关节点 |
| PoE交换机 | 相机供电+数据 | — |

### 软件

| 软件 | 版本建议 | 用途 | 许可/获取方式 |
|------|----------|------|---------------|
| **FZMotion** | 最新版 | 动捕采集、标定、骨骼绑定、CSV/FBX导出 | FZMotion许可证 |
| **Unity** | 2022 LTS+ | 双通道对比回放、偏差关节高亮 | 免费个人版 |
| **Python** | 3.9+ | CSV预处理、AI指标计算、评分融合、PDF报告生成 | 免费开源 |
| **CENI平台** | — | 未来网络实验平台，数据上传与回传 | 学校提供账号 |

### Python依赖库

| 库 | 用途 | 安装命令 |
|------|------|----------|
| **numpy** | 数值计算 | `pip install numpy` |
| **pandas** | CSV数据读取处理 | `pip install pandas` |
| **scipy** | DTW距离计算、高斯滤波 | `pip install scipy` |
| **matplotlib** | 雷达图、折线图、偏差图 | `pip install matplotlib` |
| **fpdf2** 或 **reportlab** | PDF反馈报告自动生成 | `pip install fpdf2` 或 `pip install reportlab` |
| **fastdtw** | DTW快速近似计算（备选） | `pip install fastdtw` |

### 数据格式规范

| 格式 | 用途 | 规范要求 |
|------|------|----------|
| **CSV** | 关键点时序数据 | 帧率100fps，字段命名完整（关节名_x/_y/_z），命名：学生ID-动作类型-采集序号 |
| **FBX** | 骨骼动画文件 | 可在Unity中正常加载，保留骨骼层级 |

### 关键技术参数

| 参数 | 合格阈值 | 说明 |
|------|----------|------|
| 标定重投影误差 | ≤0.5px | 摄像机标定质量 |
| CSV帧率 | 100fps | 数据采集帧率 |
| 缺帧插补后异常帧 | <1% | 预处理质量 |
| 对称性阈值 | 0.85可复现 | 评价基准 |
| 关键帧角度RMSE误差 | <3° | 指标计算精度 |
| 双通道帧同步误差 | ≤2帧 | Unity回放同步 |
| 偏差高亮准确率 | ≥90% | 偏差>15°关节标注 |
| CENI端到端回传延迟 | ≤500ms | 网络传输性能 |

### 数据流架构

```
演员 → [动捕服+39标记点] → FZMotion(标定+T-Pose+采集)
    → CSV关键点时序 + FBX骨骼动画
    → CENI上传 → AI分析服务(Python)
    → ROM/DTW/对称性/RMSE四维评分 → 0-100综合评分
    → PDF个性化反馈报告
    → CENI回传 → Unity双通道对比回放
```

## 案例3：项目/设计型 — 技术栈

### 硬件

| 设备 | 用途 | 备注 |
|------|------|------|
| Swift30红外相机 | 动捕空间搭建 | 同案例2共用 |
| 动捕服+反光标记点 | 演员穿戴 | 演播动作捕捉 |
| 图形工作站(高性能) | 运行MotionBuilder+UE同时 | UE渲染需要大量GPU资源 |

### 软件

| 软件 | 版本建议 | 用途 | 许可/获取方式 |
|------|----------|------|---------------|
| **FZMotion** 或 **Motive** | 最新版 | 动捕采集与标定 | 视实验室设备而定 |
| **MotionBuilder** | 2023+ | 数据接入、模型匹配、骨骼绑定、角色化 | Autodesk教育许可 |
| **Unreal Engine** | 5.x | 虚拟演播场景、数字人实时驱动、灯光、机位 | 免费开源 |
| **LiveLink Plugin** | 随UE版本 | MotionBuilder↔UE实时数据传输 | UE内置 |
| **AI脚本工具** | ChatGPT/Claude等 | 生成主持词、台词、动作提示、场景切换提示 | API或Web版 |
| **SDN控制器** (可选) | — | 未来网络路径优化对比 | 实验室平台 |

### AI脚本生成需求

| 生成内容 | 说明 |
|----------|------|
| 主持词/数字人台词 | 根据演播主题生成 |
| 动作提示 | 配合台词的肢体动作建议 |
| 场景切换提示 | 机位切换时机与方式 |
| 动作评价维度建议 | 演播效果评价指标 |

### 关键技术参数

| 参数 | 合格阈值 | 说明 |
|------|----------|------|
| 基础动作连续驱动 | ≥60秒 | 稳定性基本要求 |
| 故障定位时间 | ≤20分钟 | 诊断效率 |
| UE场景最低要素 | 1数字人+1演播区+1背景区+2机位+灯光 | 场景丰富度 |

### 数据流架构

```
演员 → [动捕服+标记点] → FZMotion/Motive(标定+T-Pose+采集)
    → MotionBuilder(数据接入+模型匹配+骨骼绑定+角色化)
    → LiveLink → Unreal Engine(虚拟演播场景+数字人+灯光+机位)
    → AI脚本辅助(台词+动作+切换)
    → 网络传输(普通路径 vs SDN优化路径)
    → 远程观看端
```

## 案例4：项目/设计型 — 技术栈

### 硬件

| 设备 | 用途 | 备注 |
|------|------|------|
| FZMotion动捕系统+Swift30相机 | 动作捕捉 | 同案例2共用 |
| 动捕服+标记点 | 演员穿戴（应急抢修动作） | 动作幅度较大，需注意遮挡 |
| 图形工作站 | UE+核心网展示 | — |

### 软件

| 软件 | 版本建议 | 用途 | 许可/获取方式 |
|------|----------|------|---------------|
| **FZMotion** | 最新版 | 动捕采集、标定、骨骼数据输出 | FZMotion许可证 |
| **MotionBuilder** | 2023+ | 骨骼绑定、数据中转 | Autodesk教育许可 |
| **Unreal Engine** | 5.x | 虚拟灾害场景、数字抢修人员驱动 | 免费开源 |
| **未来网络平台** (核心网子平台) | — | 应急终端接入、用户注册、会话建立、视频回传、业务优先保障 | 学校实验平台 |
| **AI评价模块** | Python实现 | 动作规范性/任务流程/网络恢复/协同效率多维评分 | 自主开发 |

### AI评价模块需求

| 评价维度 | 输入 | 输出 |
|----------|------|------|
| 动作规范性 | 动捕骨骼数据 | 动作是否标准、偏差量化 |
| 任务流程完整性 | 动作时间序列+任务脚本 | 是否按序完成所有步骤 |
| 网络恢复效果 | 核心网状态数据 | 恢复时间、业务连续性评分 |
| 团队协同效率 | 多人动作时间戳 | 配合默契度、响应时间 |

### 关键技术参数

| 参数 | 要求 | 说明 |
|------|------|------|
| 认知决策点 | ≥3个 | 场景设计要求 |
| 失败与迭代 | ≥1次 | 过程证据要求 |

### 数据流架构

```
演员(抢修人员) → [动捕服+标记点] → FZMotion(采集)
    → MotionBuilder(骨骼绑定)
    → LiveLink → UE(虚拟灾害场景+数字抢修人员)
    → 未来网络核心网平台(终端接入/注册/会话/视频回传)
    → AI评价模块(动作+流程+网络+协同多维评分)
    → 演练评分+问题诊断+改进建议
    → 远程学生端观看/参与
```

## 硬件资源排期建议（避免冲突）

> 关键约束：动捕空间同一时间只能有一个案例使用。W2-W4 为动捕空间使用高峰期，需提前预约排期。
